# ADF Studio Internationalization (i18n)

## Locales

| Code | Language |
|------|----------|
| `en` | English (source of truth for keys) |
| `id` | Bahasa Indonesia (required pair) |

Switching: **TopBar** (`ID` / `EN`) or **Settings → Bahasa**. Preference is stored in `localStorage` (`adf.studio.language.v1`).

## Catalog

- Source: `adf-studio/src/i18n/messages.ts`
- Hook: `useT()` from `@/i18n`
- Helper: `t(language, key, vars?)`, `navKey(id)`

## Mandatory rule for every new UI progress

**Setiap fitur / halaman / string UI baru WAJIB punya pasangan EN + ID di katalog yang sama.**

1. Add the key to the `en` object in `messages.ts`.
2. Add the **same key** to the `id` object (Bahasa Indonesia).
3. Use `const t = useT();` + `t("your.key")` in components — do **not** hardcode user-facing English (or Indonesian) in JSX for new work.
4. If a page is only partially migrated, migrate the title/subtitle/nav first, then body copy.
5. Update this note / acceptance when a large surface is fully localized.

## Coverage (current baseline)

| Surface | Status |
|---------|--------|
| Welcome / Demo / Help / Settings | ✅ EN+ID |
| Sidebar navigation | ✅ EN+ID |
| TopBar / StatusBar | ✅ EN+ID |
| Dashboard / Projects / Runtime titles | ✅ EN+ID |
| Identity hub (primary strings) | ✅ EN+ID |
| Remaining page bodies (Collab/Orch/Enterprise/…) | 🟡 incremental — add keys as those pages are touched |

## Definition of done for a UI PR

- [ ] No new hardcoded user-facing strings in touched files
- [ ] Every new `MessageKey` exists in both `en` and `id`
- [ ] Language toggle still switches the changed strings
