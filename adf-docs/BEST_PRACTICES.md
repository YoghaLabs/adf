# Best Practices

## Why This Page Exists

Lists durable operating habits that keep ADF resumable across humans and AIs.

## Practices

1. **Boot before edit** — follow `.adf/AI_BOOT.md`.
2. **SSOT first** — change `.adf` when reality changes; don’t hoard status in chat.
3. **Additive docs** — expand, don’t erase foundation pages.
4. **Explain why** — every new markdown should justify its existence.
5. **One BUILD** — finish and hand off before starting the next.
6. **Small commits** — BUILD-scoped messages when shipping increments.
7. **Link, don’t clone** — avoid duplicating status tables everywhere.
8. **Review gates matter** — honor Architecture Review when required.
9. **No placeholders** — if content isn’t ready, don’t create the file yet (unless the BUILD requires it with real content).
10. **Keep indexes honest** — update `FILE_INDEX` / `KNOWLEDGE_INDEX` with new important files.

## Anti-Practices

- Inventing new top-level folders for convenience
- “Temporary” notes that become the real state
- Starting BUILD-00N+1 to fix unfinished BUILD-00N work without a handoff
