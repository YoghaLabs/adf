# Value Proposition

## Objective

Describe ADF’s value for distinct audiences without hype or unsupported claims.

## Background

ADF keeps documentation, architecture, build state, and AI operating contracts in
the repository so humans and AI participants can continue work with shared context.

## Current Situation

Value today is grounded in `1.0.0-rc1`: Core engines, SDK/distribution surfaces,
Studio, collaboration, planning orchestration, and governance foundations. Commercial
edition benefits beyond Community are packaging, support, and enterprise operational
commitments — not imaginary features.

## Analysis

Different audiences buy different outcomes: individual clarity, team continuity,
organizational governance, or institutional accountability. One slogan cannot cover all.

## Strategy

| Audience | Value |
|----------|--------|
| **Developers** | Structured, resumable AI-assisted work with clear contracts and docs |
| **Teams** | Shared project truth, collaboration model, less context loss between sessions |
| **Software companies** | Repeatable delivery process; Professional path for commercial use and support |
| **Enterprise** | Governance, audit orientation, controlled collaboration, deployment options under Enterprise packaging |
| **Government** | Transparency, documentation discipline, auditable process posture suitable for institutional review |
| **System integrators** | Framework + packages/templates for client delivery under commercial terms |
| **Educational institutions** | Community Edition for learning, research, and non-commercial development |

## Recommendations

1. Match audience to edition in sales conversations (see `UPGRADE_PATH.md`).
2. Do not claim production SSO IdP wiring or autonomous multi-agent execution as current value (out of RC1).
3. Keep Community value real for developers and education.

## Implementation Plan

Reuse this table in Sales and Marketing phases without inventing new audiences casually.

## Deliverables

Audience value map for GTM and investor narratives.

## Risks

| Risk | Mitigation |
|------|------------|
| Overstating enterprise readiness | Tie claims to RC1 + edition packaging language |
