# Buyer Personas

## Objective

Define buyer and influencer personas for ADF evaluations.

## Background

ICP describes organizations; personas describe people who evaluate, champion, or
block adoption.

## Current Situation

ADF sales motions (when commercialized) will touch technical leadership first.
Procurement and security appear later for Enterprise.

## Analysis

Personas differ by success metric: architecture integrity, team throughput,
institutional compliance, or agency delivery margins.

## Strategy

### CTO

| Field | Detail |
|-------|--------|
| Goals | Reduce delivery risk; set AI engineering standards |
| Concerns | Tool sprawl, lock-in narrative, governance readiness |
| Success signal | Clear platform decision with accountable operating model |
| Message focus | Framework/platform identity; SSOT; human decision authority |

### Engineering Manager

| Field | Detail |
|-------|--------|
| Goals | Predictable team delivery; onboarding; fewer context-loss failures |
| Concerns | Learning curve; disruption to current toolchain |
| Success signal | Team can resume AI-assisted work across sessions |
| Message focus | Collaboration model; Studio as control center; Community pilot path |

### Tech Lead

| Field | Detail |
|-------|--------|
| Goals | Enforce architecture and documentation quality |
| Concerns | Yet another process; docs that go stale |
| Success signal | Contracts/ADRs actually used by humans and AI participants |
| Message focus | Documentation-first; architecture-first; repository-native state |

### Solution Architect

| Field | Detail |
|-------|--------|
| Goals | Coherent system boundaries; integration with existing platforms |
| Concerns | Category confusion; overlap with IDP/DevOps |
| Success signal | Clean fit diagram vs assistants, PM, DevOps, knowledge tools |
| Message focus | Competitive category map; packaging (Core/Studio/SDK) |

### Government IT Manager

| Field | Detail |
|-------|--------|
| Goals | Accountability, documentation, controlled adoption |
| Concerns | Hype, vendor opacity, unsupported claims, RC vs GA clarity |
| Success signal | Honest capability statement + audit/governance posture |
| Message focus | Transparency; lifecycle stage; Enterprise focus without overclaim |

### Software House Owner

| Field | Detail |
|-------|--------|
| Goals | Margin, repeatability, commercial clarity for client work |
| Concerns | License for commercial use; support; training cost |
| Success signal | Professional edition path with usable Community evaluation |
| Message focus | Commercial rights; delivery repeatability; upgrade path |

## Recommendations

1. Identify primary persona per opportunity; do not pitch all six identically.
2. Bring Solution Architect into category-framing early.
3. For government, lead with honesty and process — not feature volume.

## Implementation Plan

Marketing creates persona-tailored briefs from this SSOT without adding hype.

## Deliverables

Six personas for discovery and content.

## Risks

| Risk | Mitigation |
|------|------------|
| Persona pitch invents features | Tie messages to RC1 + labeled roadmap |

## Success Metrics

Discovery notes name persona + edition hypothesis.
